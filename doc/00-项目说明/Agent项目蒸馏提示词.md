# Java / RuoYi 项目蒸馏提示词

本文用于指导 Codex 理解、盘点、注释化和模板化当前 Java / RuoYi 项目。

## 项目背景

当前分支是 `devlop`，从 `main` 分支切出。

`main` 是已经完成真实业务开发的分支，但存在以下问题：

- 注释不完整。
- 业务逻辑和基础框架混在一起。
- 项目知识主要散落在代码里。
- Codex 每次接手时需要重新理解，容易重复踩坑。
- 当前目标不是立即重构或删除业务，而是先做项目蒸馏。

## 蒸馏目标

请把当前项目从“业务代码集合”蒸馏成“Codex 和开发者都容易理解、复用、裁剪的项目模板”。

重点输出：

- 项目地图。
- 基础能力边界。
- 项目业务边界。
- 可抽象示例。
- 待确认逻辑。
- 方法注释和步骤注释。
- Agent 使用规则。
- 常见坑和护栏。

## 必须使用的本地 Skills

处理本项目时，优先使用以下本地 skills：

- `xms-project-style`
- `utf8-safe-editing`
- `method-comments-required`

要求：

- 先按 `xms-project-style` 理解项目结构、模块边界和验证命令。
- 修改中文文档、Java 注释、SQL 注释、Vue 文案时，必须按 `utf8-safe-editing`，避免乱码。
- 修改或补充 Java 业务代码注释时，必须按 `method-comments-required`，不能只给入口方法加注释，调用链 helper 也要补方法注释，复杂逻辑要补步骤注释。

## 推荐工作方式

### 1. 先盘点，不改代码

适合刚进入项目时使用：

```text
请先盘点当前 Java / RuoYi 项目，不要改代码。
输出后端模块、前端页面、核心表、Controller、Service、Mapper、定时任务、异步消费者、外部回调入口。
```

### 2. 建立项目地图

```text
请建立项目地图。
按后端模块、前端页面、表结构、定时任务、异步消费者、外部回调、钱包/订单/用户等基础能力分类。
```

### 3. 做边界划分

```text
请把当前项目代码分成四类：
【基础能力】所有项目都可能复用的能力。
【项目业务】当前项目特有业务。
【可抽象示例】可以作为模板示例但不一定保留真实业务。
【待确认】代码行为不清楚，不能猜测。
```

### 4. 梳理链路

```text
请梳理某个业务链路。
从 Controller 到 Service 到 Mapper/XML，再到状态变更、钱包变动、异步消息、定时任务。
不要改代码，只输出调用链和当前代码真实规则。
```

### 5. 反向文档化

```text
请根据现有代码反向文档化当前流程。
不要假设需求，只写代码当前真实行为。
标明入口、核心表、状态流转、副作用、幂等规则和风险点。
```

### 6. 可读化改造

```text
请对指定链路做可读化改造。
只补方法注释、调用链 helper 注释、复杂步骤注释和 Mapper SQL 规则注释。
不要改变业务逻辑，不要重构，不要格式化无关代码。
```

### 7. 风险审计

```text
请对指定链路做风险审计。
重点检查重复执行、事务边界、并发、N+1 查询、金额精度、幂等、状态抢占、钱包发放风险。
不要改代码，只列风险、证据和建议。
```

### 8. 知识固化

```text
请把这次踩坑或经验固化到文档或 agent skill 中。
要求以后遇到类似场景时自动检查，避免重复造轮子。
```

## 常用关键词

和 Codex 沟通时，可以使用这些关键词让它更快进入正确模式：

- 蒸馏：从现有代码中提炼可复用知识。
- 盘点：先摸清楚项目有什么，不改代码。
- 梳理链路：沿调用链理解业务。
- 反向文档化：根据代码真实行为生成文档。
- 可读化改造：只补注释和说明，不改逻辑。
- 边界划分：区分基础能力、项目业务、可抽象示例、待确认。
- 风险审计：用 review 视角找资金、状态、事务、幂等风险。
- 约束提炼：从代码里提炼以后必须遵守的开发规则。
- 模板化：把项目整理成后续新项目可复制的起点。
- 最小闭环：做一个小而完整、能跑通的 demo。
- 调用链注释化：入口方法、helper、SQL、复杂步骤都补注释。
- 决策记录 ADR：记录为什么这样设计。
- 不变量：提炼业务必须永远成立的条件。
- 护栏：把容易踩坑的地方变成检查规则。

## 当前阶段建议

当前阶段优先顺序：

1. 只读盘点项目，不改代码。
2. 建立项目地图。
3. 做基础能力和项目业务边界划分。
4. 选择核心基础链路做注释化，比如用户、钱包、充值、提现、订单、异步、定时任务。
5. 把踩坑点固化到文档和 skills。
6. 最后再考虑删除强业务或整理模板 demo。

## 禁止事项

除非明确要求，否则不要：

- 删除业务代码。
- 重构业务逻辑。
- 改变接口行为。
- 执行数据库迁移。
- 格式化大范围文件。
- 在不理解业务的情况下猜测需求。
- 用 PowerShell 默认编码写中文文件。
- 只给入口方法加注释而忽略调用链 helper。
