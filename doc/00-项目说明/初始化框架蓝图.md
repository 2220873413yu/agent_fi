# 初始化框架蓝图

本文用于说明 XMS 项目作为“初始化框架”时建议保留的基础能力、可选业务边界和标准示例入口。第一阶段不裁剪现有业务代码，只沉淀框架口径和可复制样例。

## 框架定位

初始化框架不是 RuoYi 空壳，而是一个带资金、订单、异步和定时结算底座的业务基础项目。

适合作为新项目起点的能力：

- 注册、登录、认证、权限、菜单、字典。
- 用户体系、上下级关系、基础用户资料。
- 钱包余额、钱包流水、余额增加和扣减。
- 充值记录、充值回调、入账处理。
- 提现申请、审核、扣款、驳回退回、打款回调。
- 订单创建、订单状态流转、订单后置处理。
- Redis Stream 异步消费、Redisson 延迟队列、事务提交后投递消息。
- Quartz 定时任务扫描、任务派发、结算/奖励批量发放。

不建议放进“干净框架”的强业务能力：

- Polymarket 具体交易、盘口、结算规则。
- 质押托管的复杂 G7、全球分红、团队奖励算法。
- 节点认购的具体套餐、释放比例和业务参数。
- 某个项目特有的 OpenAI、商城、Diy 页面等业务。

这些能力可以作为可选业务模块保留在 `doc/02-业务模块/`，新项目按需要迁移。

## 标准示例入口

示例代码放在 `main/example` 包，仅供复制参考，不参与运行：

- `xms-dao/src/main/java/com/xms/dao/example/WalletOperationExample.java`
- `xms-dao/src/main/java/com/xms/dao/example/WalletBatchRewardExample.java`
- `xms-dao/src/main/java/com/xms/dao/example/AsyncOrderFlowExample.java`
- `xms-dao/src/main/java/com/xms/dao/example/RechargeWithdrawExample.java`
- `xms-agent-admin/src/main/java/com/xms/web/example/ScheduledSettlementExample.java`

示例包规则：

- 不加 `@Service`、`@Component`、`@RestController`、`@Scheduled`。
- 不新增真实接口、菜单、表或任务。
- 示例方法通过参数传入依赖，避免被 Spring 自动注入和运行。
- 复制到真实业务前，必须确认业务类型、币种、状态值、来源 ID 和事务边界。

## 基础框架裁剪原则

如果后续要真正裁剪为初始化项目，建议按以下顺序处理：

1. 先保留 RuoYi 基础模块、用户、钱包、充值、提现、订单、异步、定时任务。
2. 把 Polymarket、复杂托管、节点套餐等强业务迁移到可选模块。
3. 表结构分为 `baseline` 和 `optional`，不要把强业务表混进基础初始化 SQL。
4. 前端只保留系统管理、用户、钱包、充值、提现、订单和任务监控等通用页面。
5. 每删除一个业务模块，同步删除菜单、字典、接口文档、SQL 和定时任务配置。

## Agent 使用口径

新项目要基于 XMS 初始化框架开发时，可以这样要求 Agent：

```text
先阅读 doc/00-项目说明/初始化框架蓝图.md 和 doc/01-基础能力/标准能力索引.md。
涉及钱包变动时按 xms-wallet-settlement。
涉及复杂订单后置处理时按 xms-async-business-flow。
涉及定时任务结算时优先采用“扫描待处理数据 -> 状态抢占 -> 批量落库 -> 失败回滚”的模式。
```
