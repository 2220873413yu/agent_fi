# 示例质押模块

## 定位

示例质押模块是初始化项目里的标准业务样板，用来演示一条完整的“下单、扣款、异步处理、业绩更新、订单完成”链路。

该模块不代表真实生产质押规则，不承载复杂托管、动态奖励、全球分红、节点等级、加速释放等业务。后续新项目可以复制该模块作为参考，也可以在不影响基础框架的情况下删除。

## 目标

- 演示 RuoYi 后台菜单、Controller、Service、Mapper、Vue 页面和菜单 SQL 的标准写法。
- 演示单用户扣款如何通过钱包标准入口完成，并自动保留钱包流水来源。
- 演示复杂订单如何先落库状态，再通过 Redis 异步消费。
- 演示消费前按订单状态抢占，避免重复处理。
- 演示用户基础业绩字段的更新口径：
  - 个人业绩：`performance`
  - 直推业绩：`sub_performance`
  - 团队业绩：`performance_mining` / `umbrella_performance`
  - 小区业绩：`community_performance`

## 模块边界

建议模块命名使用 `DemoPledge`，表名使用 `t_demo_pledge_*`，避免和真实质押业务 `stake_*`、`stake_hosting_*` 混淆。

后台菜单建议放在：

```text
示例业务
  - 示例质押套餐
  - 示例质押订单
```

## 状态流

```text
0 待支付
  -> 扣款成功
1 已支付
  -> Redis 消费者抢占成功
2 处理中
  -> 业绩更新成功
3 已完成
  -> 处理异常
4 失败
```

状态说明：

- `待支付`：订单已创建，但还没有扣款成功。
- `已支付`：钱包扣款成功，等待异步消费者处理业绩。
- `处理中`：消费者已抢占订单，正在处理业绩。
- `已完成`：业绩处理完成。
- `失败`：异步处理失败，记录失败原因，后续可人工补偿或定时任务重试。

## 标准流程

### 1. 创建订单并扣款

购买套餐时，主流程做以下事情：

```text
1. 查询套餐，校验套餐启用。
2. 创建订单，状态为待支付。
3. 调用钱包标准入口扣 USDT。
4. 扣款成功后，订单改为已支付。
5. 事务提交后投递示例质押独立 Redis Stream 消息。
```

钱包扣款使用标准入口：

```java
String code = IDUtils.getSnowflakeStr();
int count = userWalletServiceImpl.handerUserMoney(
    pledgeUsdtAmount.negate(),
    code,
    userId,
    orderId,
    ConstantType.user_money_log_source_type.type_xx,
    ConstantType.COIN_USDT
);
if (count != 1) {
    throw new ServiceException(ResponseCode.CODE_1015);
}
```

注意：`sourceId` 建议使用订单ID，`sourceCode` 使用订单号或本次钱包变动流水号，方便追踪。

### 2. 事务提交后投递独立 Redis Stream

Redis 消息只作为触发器，数据库订单才是事实来源。事务内需要发送消息时，使用 `afterCommit`：

示例质押不要复用正式业务的 `ORDER_DYNAMIC_SETTLEMENT` 总队列，应使用独立队列，例如：

```java
RedisConstant.StreamMsgConstant.DEMO_PLEDGE_ORDER
```

```java
TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
    @Override
    public void afterCommit() {
        sendDemoPledgeOrderMessage(orderId);
    }
});
```

消息体只放最小字段：

```json
{
  "orderId": 123
}
```

### 3. 消费者处理订单

消费者处理时不能直接相信消息体，必须重新查询订单：

```text
1. 根据 orderId 查询订单。
2. 只处理 status = 已支付 的订单。
3. 先把订单从 已支付 抢占为 处理中。
4. 抢占成功后再计算业绩。
5. 业绩更新成功后，订单改为 已完成。
6. 处理失败时，订单改为 失败 并记录 fail_reason。
```

抢占更新示例：

```sql
UPDATE t_demo_pledge_order
SET status = 2,
    process_time = NOW(),
    update_time = NOW()
WHERE id = ?
  AND status = 1
  AND deleted = 0;
```

返回行数为 `1` 才代表抢占成功。

## 业绩更新口径

示例质押金额记为 `pledge_usdt_amount`。

### 个人业绩

购买用户增加个人业绩：

```sql
UPDATE t_user_info
SET performance = performance + ?
WHERE user_id = ?;
```

### 直推业绩

如果购买用户存在直接上级 `invite_user_id`，直接上级增加直推业绩：

```sql
UPDATE t_user_info
SET sub_performance = sub_performance + ?
WHERE user_id = ?;
```

### 团队业绩

购买用户父级链上的所有上级增加团队业绩：

```sql
UPDATE t_user_info
SET performance_mining = performance_mining + ?,
    umbrella_performance = umbrella_performance + ?
WHERE user_id IN (...);
```

### 小区业绩

小区业绩通常需要基于团队各条线业绩重新计算。示例模块可以先采用简化口径：

```text
小区业绩 = 团队业绩 - 最大单线业绩
```

第一版可以在消费者处理完成团队业绩后，针对受影响上级重新计算 `community_performance`。如果新项目不需要小区业绩，可删除该步骤。

## 批量落库建议

示例模块第一版可以先用清晰的 SQL 更新演示流程。如果后续要模拟大量订单或批量奖励，建议采用“批量结算收集-落库模式”：

```text
1. 先收集需要更新的用户业绩。
2. 聚合同一用户的增量。
3. 使用 JdbcTemplate.batchUpdate 批量落库。
4. 任一关键更新失败则回滚或标记失败。
```

## 实现注意事项

- 示例模块不写真实复杂收益率，不做每日收益，不做全球分红。
- 钱包扣款必须走标准钱包入口，不能直接改 `t_user_money`。
- Redis 消息只放 `orderId` 等最小字段，不放大 JSON。
- 消费前必须重新查订单状态。
- 消费者必须先抢占状态，抢占失败直接跳过。
- 业绩字段更新要保留事务边界，失败时订单不要误标完成。
- 示例代码和真实业务代码要通过包名、表名、菜单名明显隔离。
